# A股量化盯盘助手 — 设计文档

- 日期: 2026-06-25
- 状态: 已与用户确认,待进入实施计划
- 作者: 与 Claude 协作 brainstorm

## 1. 背景与目标

用户希望搭建一个 A股量化系统,定位为**辅助决策的盯盘助手**(程序提醒,用户手动下单),而非全自动交易。用户会 Python,是量化新手,需要边做边学。

核心价值:系统不直接动用户的钱(无自动下单),信号写错最多发一条无用提醒,风险极低,非常适合作为量化入门的起步形态。

### 用户画像
- **目标**: 辅助决策(程序提醒,人工下单)
- **市场**: A股(沪深)
- **风格**: 盘中日内(当天进出,人工下单)
- **技术**: 会 Python
- **关注信号**: 经典技术指标(均线金叉死叉、MACD、RSI、突破)+ 量价异动(放量、急拉急跌、破当日高低点)
- **需求范围**: 盯盘监控 + 选股筛选 + 回测验证,三者都要

### 数据现实约束
- 真高频(秒级以下、靠速度抢单)已明确排除:必须全自动,且免费数据源拿不到对应通道。
- 免费源(akshare)可提供:实时盘口快照、分钟K线、日线、基本面、交易日历。轻微延迟,对"盘中日内提醒"这种非高频场景完全够用。
- 轮询间隔建议 30~60 秒,避免被数据源限流。

## 2. 架构总览

三条流水线共用一套底层模块。规则一律采用"注册表"模式,加功能 = 写一个函数 + 注册一行,不动其它模块。

```
                    ┌─────────── 共用底层 ───────────┐
                    │  数据层 (实时行情 / 分钟K / 日线 / 基本面 / 交易日历)
                    │  指标层 (MA/MACD/RSI/量价... 纯函数)
                    │  提醒层 + 日志层
                    └────────────────────────────────┘
                  ▲                  ▲                  ▲
     ┌────────────┘                  │                  └────────────┐
     │                               │                               │
【选股流水线】盘前/盘后        【盯盘流水线】盘中每N秒          【回测流水线】离线
     │                               │                               │
全市场→日线+基本面               实时行情+分钟K                历史数据回放→同一批
→ SCREEN_RULES                  → MONITOR_RULES               规则函数→绩效统计
→ 生成/更新自选名单 ──────────────▶ → 提醒 + 日志
```

### 设计核心原则
- **模块隔离**: 每个模块只做一件事,通过清晰的数据结构(主要是 DataFrame 和 Signal 对象)传递,可单独理解与测试。
- **注册表拓展**: 选股、盯盘两类规则各有一个注册表;加规则 = 加函数 + 注册一行。
- **规则即纯函数**: 信号规则输入带指标的 DataFrame、输出触发与否。同一份规则代码在实时盯盘和历史回测中复用,这是回测模块零重写逻辑的关键。
- **数据源隔离**: 数据层对外只暴露稳定接口,以后换 tushare / 券商源只改这一层。

## 3. 模块职责

### 3.1 配置层
- 一个 config 文件,集中放:自选股名单、各信号阈值、轮询秒数、提醒冷却时间、提醒通道开关。
- 改行为只动这里。

### 3.2 数据层
- 封装 akshare,对外暴露稳定接口:
  - `get_realtime(codes)` — 实时盘口快照
  - `get_minute_bars(code)` — 分钟K线
  - `get_daily_bars(code, range)` — 日线(选股/回测用)
  - `get_fundamentals(codes)` — 基本面(选股用)
  - `get_trade_calendar()` — 交易日历
- 数据源细节全部封装在内,便于以后换源。

### 3.3 指标层
- 纯函数: `add_ma(df)`、`add_macd(df)`、`add_rsi(df)`、量价特征等。
- 输入输出都是 DataFrame,易测、易复用。

### 3.4 信号层(两个注册表)
- `MONITOR_RULES`: 盯盘信号,如 `ma_cross(df, cfg)`、`volume_spike(df, cfg)`、`break_intraday_high(df, cfg)`。
- `SCREEN_RULES`: 选股规则,如 "近5日放量 + 站上20日线 + 市值<X"。
- 每条规则输入(带指标的)DataFrame + 配置,输出 `Signal | None`(含 股票/信号名/方向/时间/触发值)。
- 加规则 = 写函数 + 注册一行,规则间互不影响,可单测。

### 3.5 提醒层
- 通道(可叠加,统一接口): 终端打印 + 桌面通知 + 声音(起步零配置);之后 Server酱 / 钉钉机器人 / 企业微信机器人(手机推送)。
- **防重复**: 同股票同信号在冷却时间(如 15 分钟)内只发一次,维护"最近已发"状态去重。
- 每条提醒携带: 股票名/代码、信号名、方向(看多/看空)、触发时间、关键数值(如 RSI=23、量比=3.2)。

### 3.6 日志/状态层
- 记录每次触发(供事后复盘 + 作为回测/分析的数据基础)。
- 维护去重所需的状态。

### 3.7 调度器
- 仅在 A股交易时段运行(9:30–11:30、13:00–15:00),用交易日历跳过周末/节假日。
- 盯盘流水线每 N 秒一轮;选股流水线盘前/盘后各跑一次。

### 3.8 回测模块(正式模块)
- 复用指标层 + 信号层的**同一批规则函数**,把实时数据换成历史数据回放,无需重写信号逻辑。
- 输出绩效统计(信号后价格走势、胜率、盈亏比等),用于筛选哪些规则值得信任。
- 必须规避三类新手坑:
  - **未来函数(look-ahead bias)**: 计算第 t 根K线信号时绝不使用 t 之后的数据。
  - **幸存者偏差**: 回测股票池须包含当时已退市/ST 的标的。
  - **交易成本**: 计入 A股佣金、印花税、滑点。

## 4. 数据流

```
配置(自选名单/阈值)
  → 调度器(交易时段、每N秒)
  → 数据层(实时行情 + 分钟K)
  → 指标层(加指标列)
  → 信号层(MONITOR_RULES 逐条判断)
  → 提醒层(去重 → 发送)
  → 日志层(记录触发)

选股线: 全市场 → 数据层(日线+基本面) → 指标层 → SCREEN_RULES → 生成/更新自选名单(喂给盯盘线;可与手填名单合并)
回测线: 历史数据 → 指标层 → 同一批规则函数 → 绩效统计
```

## 5. 分阶段实施计划

- **阶段1(MVP,最小闭环)**: 手填自选名单 → 取实时行情+分钟K → 算 MA/MACD/RSI → 1~2 条盯盘信号 → 终端/桌面提醒。目标:盘中跑通"取数→算→提醒"。
- **阶段2(盯盘完善)**: 补齐量价异动信号、防重复、触发日志、手机推送通道。
- **阶段3(选股线)**: 数据层加日线+基本面 → SCREEN_RULES → 盘前/盘后生成自选名单 → 自动喂给盯盘线。
- **阶段4(回测模块)**: 历史数据回放 + 绩效统计,规避未来函数/幸存者偏差/交易成本三坑,用于筛选规则。

建议先把阶段1做扎实,最快建立量化手感与正反馈。

## 6. 测试策略
- 指标层、信号层均为纯函数,用构造的小 DataFrame 做单元测试(已知输入 → 已知触发结果)。
- 数据层用录制的样本响应做测试,避免依赖实时网络。
- 回测模块用一小段历史数据验证绩效统计的正确性,并专门测试"无未来函数"。

## 7. 明确不做(YAGNI)
- 不做自动下单 / 对接券商交易接口。
- 不做真高频(秒级以下)。
- 不做事件驱动实时引擎等重型框架。
- 不引入 backtrader / vn.py / qlib(对当前需求过重)。
